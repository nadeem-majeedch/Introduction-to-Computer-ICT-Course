# Integrated Project — Brief

> **Weight:** 25% of the course grade · **Assigned:** L08 · **Showcase:** L32 · **[Milestones](milestones.md) · [Rubric](rubric.md)**

## What the project is

A small, working artefact of your own that **integrates concepts from at least four course modules**, carried from proposal through design to a public demonstration. The project proves synthesis: not "did you learn each module," but "can you *use* them together on a real goal."

## Choose one track

| Track | You produce | Modules most engaged |
|---|---|---|
| **A. Digital workflow solution** | A working spreadsheet-driven system (e.g., lab-equipment booking, expense tracker) with formulas, IF logic, lookups, dashboard chart, documentation, and a 3-2-1 backup plan | M3, M5, M7 (+M4 for any encoded data choices) |
| **B. Compute-in-context study** | A rigorous mini-study: collect/clean a small real dataset (≥60 rows), analyse in spreadsheets, produce 2 honest charts + a findings document with cited sources and stated limitations | M4, M5, M7 (+M6 if data collected online) |
| **C. Explain-the-machine artefact** | An educational artefact — interactive slide deck, simulator walkthrough (e.g., logic circuits), or short video series — that teaches one course topic to a non-specialist, with accessibility built in | M1, M2, M4/M5 (+M6 if web-hosted) |
| **D. Instructor-approved custom** | Your own integration — propose it at the L08 milestone with the same four-module mapping | ≥4 modules |

## Requirements (all tracks)

1. **Integration:** at least **four** modules engaged, explicitly mapped in your design document (one line per module: what it contributes).
2. **Artefact:** something demonstrable live at the showcase — a file that opens, a spreadsheet that computes, a study with real data, a deck that runs. Demos that "can't run today" lose the demonstration criterion.
3. **Documentation:** a design document (see [milestones](milestones.md)) and a final report (6–10 pages, styled document — L19 standards; headings, TOC, no walls of text).
4. **Accessibility:** your artefact and deck meet the L20 checklist (alt text, meaningful links, contrast, header rows).
5. **Integrity:** any AI-tool use is disclosed per [L28](../../lectures/L28-responsible-ai-literacy.md) and the [syllabus](../../syllabus.md#7-course-policies); you must be able to explain every part of your artefact at the showcase.
6. **Data ethics (track B):** no personal data collected without consent; no datasets that identify individuals (L26 §26.4). Public/aggregated data preferred.
7. **Scope guard:** the artefact must be *small and finished* rather than ambitious and broken — the rubric rewards integration and honesty, not ambition.

## Constraints

- **Individual or pairs** (instructor confirms at L08; pairs split roles explicitly in the design document).
- No requirement to buy anything; free tools only.
- Track B datasets: respect source licenses; cite them.
- All work submitted via the LMS in the folder structure from Lab 1 (`ict-course/project/`).

## What "good" looks like

A modest, *finished* artefact that clearly shows: correct underlying concepts (numbers, logic, data), professional documentation, honest presentation, and a design document that maps modules deliberately. The [rubric](rubric.md) shows exactly how the 25% is earned.
