## Q1 — What counts as a computer?

**Module 1 · CLO-1 · Difficulty 1/4 · Type: Multiple choice (with why)**

A washing machine has a chip that runs a wash program: it senses the load, adjusts water and drum speed, and finishes the cycle. Which statement is most defensible?

- A) It is not a computer, because it cannot run arbitrary programs.
- B) It is a general-purpose computer, because it runs a program.
- C) It contains an embedded, special-purpose computer: input (sensors/settings), processing (controller), output (motor/valve), and stored data (cycle parameters) are all present, but the programming is fixed to one job.
- D) It is a computer only when connected to the internet.

<details>
<summary>Model answer</summary>

**C.** The four-part definition (input, processing, output, storage) is satisfied by the chip and its sensors/actuators, so *a computer is present* — but its program is fixed, which makes it embedded and special-purpose, not general-purpose. A is the tempting over-correction: "not general-purpose" does not mean "not a computer". D confuses networking with computing.
</details>

## Q2 — Order and connect the milestones

**Module 1 · CLO-1 · Difficulty 1/4 · Type: Short answer**

Put in chronological order and give a one-phrase contribution for each: stored-program concept, transistor, Jacquard loom, Intel 4004, ENIAC.

<details>
<summary>Model answer</summary>

Jacquard loom (1801 — machine controlled by stored hole patterns) → ENIAC (1945 — first general-purpose *electronic* computer) → stored-program concept (1945 EDVAC report — program held in memory as data, enabling software) → transistor (late 1940s–50s — small, reliable, cool switches replacing tubes) → Intel 4004 (1971 — a whole CPU on one chip, the path to personal computing). A good answer states a *causal* link for at least one pair (e.g., transistor → 4004: reliable miniaturization made single-chip CPUs feasible).
</details>

## Q3 — Classify the machines

**Module 1 · CLO-1 · Difficulty 2/4 · Type: Short answer**

Classify: a datacentre server rack, a smartwatch, a lab desktop PC, a building's elevator controller — by scale/purpose, and justify the two hardest cases.

<details>
<summary>Model answer</summary>

Server rack → mainframe/scale-out server class (high throughput, many users); smartwatch → embedded/mobile special-purpose-leaning device (though it runs general-purpose-class OSes, its scale and purpose are wearable); desktop PC → microcomputer/personal general-purpose; elevator controller → embedded special-purpose. Hardest two, justifiably: the smartwatch (general OS on special-purpose form factor — either classification is defensible if argued) and the server rack (single "computer" vs many nodes — the rack is a *system*; the defensible answer treats the node as the computer and the rack as a scaled deployment).
</details>

## Q4 — The three-layer divide

**Module 1 · CLO-1 · Difficulty 2/4 · Type: Conceptual**

Name the three layers of the digital divide and give one intervention per layer. Why can fixing only one layer fail?

<details>
<summary>Model answer</summary>

(1) **Access** — devices and connectivity (intervention: community Wi-Fi, device loans); (2) **Skills** — the ability to use them effectively (intervention: digital-literacy training); (3) **Usage/outcome** — meaningful use for education, work, services (intervention: locally relevant services and support, e.g., assisted access desks). Fixing one layer alone fails because they chain: free laptops without skills create unused devices; skills without relevant services create capability with nowhere to apply it. A good answer notes the layers *interact* (L04's framework).
</details>

## Q5 — Von Neumann organization

**Module 2 · CLO-2 · Difficulty 1/4 · Type: Short answer**

Sketch the von Neumann organization (CPU, memory, input, output, buses) and label what travels on the buses. What is the stored-program idea's one-sentence significance?

<details>
<summary>Model answer</summary>

CPU (control unit + ALU + registers) connected via system buses (address, data, control) to memory; input and output devices attached. Buses carry: addresses (where), data (the values/instructions themselves), control signals (read/write, timing). Stored-program significance: instructions live in the same memory as data and can be manipulated like data — making software *loadable and changeable* rather than wired-in; this is the boundary between "a calculating machine" and "a programmable computer".
</details>

## Q6 — Fetch–decode–execute with a twist

**Module 2 · CLO-2 · Difficulty 2/4 · Type: Conceptual**

During execution of a load instruction, the CPU discovers the operand is not in cache but in RAM. Explain, in fetch–decode–execute terms, what happens next and why this makes the memory hierarchy matter.

<details>
<summary>Model answer</summary>

The load's execution stalls at the memory-read step: the request goes down the hierarchy (cache miss → RAM access), the value is filled into cache and the register, then execution resumes. Why the hierarchy matters: the stall costs tens-to-hundreds of cycles versus 1–3 for a cache hit, so *where data lives* dominates real performance — which is why caches, prefetching, and locality-aware code exist. A good answer connects the mechanism (miss penalty) to the design lesson (hierarchy exists to hide latency).
</details>

## Q7 — RAM, storage, and the "8 GB enough?" question

**Module 2 · CLO-2 · Difficulty 2/4 · Type: Scenario-based**

A student's laptop: 4 GB RAM, HDD 92% full, feels slow when many browser tabs are open, fast again after a reboot with few tabs. Diagnose the most likely bottleneck and justify; name one upgrade and what it would and would not fix.

<details>
<summary>Model answer</summary>

Diagnosis: memory pressure. 4 GB + many tabs → the OS swaps inactive pages to the (slow, nearly-full) HDD; performance recovers when the working set shrinks (few tabs) — the pattern matches swapping, not a dying disk or malware. Upgrade: more RAM (to 8–16 GB) removes the swapping for typical workloads; it would **not** fix general disk-space starvation (92% full still degrades update/scratch space and fragmentation-class issues on HDDs) nor CPU-bound slowness. A good answer distinguishes the *two* problems (RAM and disk space) rather than merging them.
</details>

## Q8 — RAID is not backup

**Module 2 · CLO-2 · Difficulty 2/4 · Type: True/false with explanation**

True or false, with the reason: "A server with mirrored drives (RAID 1) does not need backups."

<details>
<summary>Model answer</summary>

**False.** RAID (mirroring) protects against *one class* of failure: a drive dying. It does not protect against deletion (mirrors delete too — the deletion propagates to the mirror), ransomware encryption, fire/theft of the whole machine, or silent corruption. Backups protect against *state* loss (point-in-time copies, ideally offline/offsite — 3-2-1); RAID protects against *hardware* failure. The pairing statement: RAID buys uptime; backups buy recoverability.
</details>

## Q9 — The software stack

**Module 3 · CLO-3 · Difficulty 1/4 · Type: Short answer**

Place in the stack, top to bottom: word processor, Linux kernel, file manager, device driver, web browser, BIOS/UEFI. State the role of the two ends.

<details>
<summary>Model answer</summary>

Top: word processor, web browser, file manager (applications; order within the layer is flexibility, not hierarchy) → OS (Linux kernel — resource management, processes, hardware abstraction) → device drivers (OS↔specific-hardware translators) → firmware (BIOS/UEFI — the first code to run; initializes hardware and hands off to the bootloader). Roles: the top end *serves the user's tasks*; the bottom end *bridges hardware to software* at power-on.
</details>

## Q10 — Boot failure diagnosis

**Module 3 · CLO-3 · Difficulty 2/4 · Type: Troubleshooting**

A PC powers on, fans spin, but the screen stays black with no manufacturer logo. Another machine in the same room boots fine from the same wall socket. Using the boot sequence, state the two most likely fault points and one safe test each.

<details>
<summary>Model answer</summary>

Before the logo appears, the sequence is: power-on → firmware/POST (BIOS/UEFI) → handoff to bootloader. Two most likely points: (1) **display path** — the machine may be running fine with a dead output or wrong input; safe test: try another monitor/cable, or check for beep/LED POST codes; (2) **POST failure** — RAM/coin-cell/board fault stops boot before video init; safe test: reseat memory (unplugged), listen for beep codes, clear CMOS per the manual. A good answer refuses to jump to "dead disk" — a storage fault happens *after* the logo, so it cannot explain a black screen before POST output.
</details>

## Q11 — Paths: absolute vs relative

**Module 3 · CLO-3 · Difficulty 1/4 · Type: Short answer**

Current directory: `C:\Users\sami\Documents`. Write the absolute and relative paths for `notes.txt` stored in `C:\Users\sami\Documents\courses\ict\`. Then the file moves to `C:\archive\` — which path breaks?

<details>
<summary>Model answer</summary>

Absolute: `C:\Users\sami\Documents\courses\ict\notes.txt`. Relative: `courses\ict\notes.txt`. After the move, the **relative** path breaks (the relationship from the current directory changed); the absolute path is *invalid* (the file is gone from that location) but was never ambiguous. The teaching point: absolute paths are location-independent but verbose; relative paths are portable *with* their working directory — which is exactly why moved projects and broken shortcuts happen.
</details>

## Q12 — The update you keep postponing

**Module 3 · CLO-3 · Difficulty 2/4 · Type: Conceptual**

Why do security updates outrank feature updates, mechanically? A student defers a security patch "until after exams" — what specific risk accumulates, and what middle path keeps both integrity and convenience?

<details>
<summary>Model answer</summary>

Mechanically: security patches close *known* vulnerabilities — knowledge of the hole exists (often public via advisories), so exploits can be built against machines that lack the fix; feature updates add capability with no such clock. Deferring accumulates **exposure to already-public attacks**: the machine is a known-vulnerable target for the deferral window. Middle path: active hours + scheduled reboot windows so patching lands predictably (the OS's own tooling), or defer days-not-months with the machine off untrusted networks in the gap. A good answer rejects the permanent-disable over-correction and names the clock (public knowledge → exploit availability).
</details>

## Q13 — Why base 2?

**Module 4 · CLO-4 · Difficulty 2/4 · Type: Conceptual**

Give the hardware-economics argument for binary, and one counter-pressure that once pushed designers toward other bases.

<details>
<summary>Model answer</summary>

Binary needs circuits that distinguish just two states (on/off, high/low voltage) — cheap, fast, and *noise-tolerant*: anything above the threshold is 1, below is 0, so small signal degradation doesn't corrupt values. More states per symbol (e.g., ternary, multi-level flash cells) pack more information per wire/cell but need finer voltage discrimination, which costs speed, noise margin, and reliability — the economics favoured binary. Counter-pressure, stated honestly: multi-level *NAND flash* stores 3+ bits/cell (QLC = 16 levels) — accepted where density is worth the cost, and modems/multi-level signalling exist on wires. The point: base 2 won on switching economics, not on information density.
</details>

## Q14 — Convert with method

**Module 4 · CLO-4 · Difficulty 1/4 · Type: Data representation exercise**

Convert, showing method: (a) decimal 200 → binary → hex; (b) hex `0x2F` → decimal; (c) octal `144₈` → decimal.

<details>
<summary>Model answer</summary>

(a) 200 = 128+64+8 → `1100 1000₂` → grouping nibbles: `C8₁₆`. (b) `0x2F` = 2×16 + 15 = **47**. (c) `144₈` = 1×64 + 4×8 + 4 = **100**. Method marks: repeated division by 2 (and by 16) for (a); positional expansion for (b) and (c). A correct final answer with no method earns half — the method is the assessed skill.
</details>

## Q15 — Two's complement, three moves

**Module 4 · CLO-4 · Difficulty 2/4 · Type: Data representation exercise**

In 8-bit two's complement: (a) encode −45; (b) decode `1011 0110`; (c) compute 100 + 50 and name the phenomenon.

<details>
<summary>Model answer</summary>

(a) +45 = `0010 1101` → invert `1101 0010` → +1 → **`1101 0011`**. (b) MSB is 1 → negative: invert `0100 1001` → +1 → `0100 1010` = 74 → **−74**. (c) 100 + 50 = 150, but 8-bit signed range is −128…+127: result `1001 0110` = −106 → **overflow** (the sum left the representable range; the hardware flag notes it, and whether software checks is language/runtime-dependent). A good answer shows the inversion+1 steps, not just results.
</details>

## Q16 — UTF-8 and the mojibake

**Module 4 · CLO-4 · Difficulty 2/4 · Type: Troubleshooting**

A file created on one machine shows `Ã©` where an `é` should be on another. Explain the mechanism in one paragraph (encodings, bytes), and state the general fix.

<details>
<summary>Model answer</summary>

Mojibake: the bytes were written using one encoding and *read as another*. `é` in UTF-8 is the two-byte sequence `0xC3 0xA9`; a reader assuming Latin-1 (one byte per character) decodes `0xC3` as `Ã` and `0xA9` as `©` — producing `Ã©`. The bytes are intact; the *interpretation* was wrong. General fix: make the encoding explicit end-to-end — declare UTF-8 at writing (and in transfer metadata), read with UTF-8; for an existing misread file, reinterpreting the bytes as UTF-8 (not re-typing) recovers the text. Good answers distinguish "corrupted bytes" from "misinterpreted bytes" — the latter is the common case and is recoverable.
</details>

## Q17 — Lossy or lossless?

**Module 4 · CLO-4 · Difficulty 1/4 · Type: Comparative**

Match a mode with a reason: a scanned contract (PDF), a streaming movie, a source-code archive (ZIP), a podcast episode.

<details>
<summary>Model answer</summary>

Contract → **lossless** (text/fidelity: any character loss is information loss; PDF typically embeds lossless or high-fidelity streams); streaming movie → **lossy** (video codecs trade imperceptible detail for bandwidth; the stream is consumed, not archived); ZIP archive → **lossless** (archives must reconstruct exact bytes — lossy compression would corrupt the code); podcast → **lossy** (speech codecs discard frequencies below perception; convenience of size wins). A good answer adds the principle: lossy for *human-perception* media, lossless wherever exactness matters.
</details>

## Q18 — The 7 GB folder that "isn't full"

**Module 4 · CLO-4 · Difficulty 3/4 · Type: Troubleshooting**

A folder of 2,000 small files reports far larger on disk than the sum of file sizes. Two mechanisms explain it — name both and state which the file manager's number includes.

<details>
<summary>Model answer</summary>

(1) **Binary vs decimal prefixes**: the tool's "GB" may be GiB (1,073,741,824 B) vs GB (10⁹) — a ~7% gap by itself. (2) **Allocation/block overhead**: files occupy whole allocation units, so thousands of small files consume far more than their content bytes (a 200-byte file on a 4 KiB-cluster volume uses ≥4 KiB). The file manager's *size-on-disk* includes overhead; *size* usually reports content bytes — hence the mismatch. Good answers name both mechanisms and the tool-dependence of which number appears.
</details>

## Q19 — Slow PC triage order

**Module 4 · CLO-4 · Difficulty 3/4 · Type: Scenario-based**

"Small office PC, 5 years old: slow at startup, slow when many windows open, disk light constantly on." Diagnose the two most consequential problems in order, justify the order, and name one measurement that would confirm each.

<details>
<summary>Model answer</summary>

Order: (1) **Memory pressure → swapping** (many windows + constant disk light = the OS paging to disk; disk activity is the *symptom* of the memory problem); measurement: memory-in-use vs installed RAM, or page-fault/hard-fault counters in Task Manager. (2) **HDD age/fullness** (a nearly-full, 5-year-old HDD adds latency everywhere; startup slowness fits); measurement: disk free % and a health check (S.M.A.R.T. attributes). Justification: fix (1) and the disk light calms even on a mediocre HDD; fix (2) without (1) leaves swapping in place. The *ordering rationale* is the marked skill — the same items in reverse order show missed causal reasoning. (Follow-up noted in the answer: an SSD upgrade addresses (2) directly; RAM addresses (1).)
</details>

## Q20 — Update loop, safely broken

**Module 4 · CLO-4 · Difficulty 3/4 · Type: Troubleshooting**

Every evening an update installs at shutdown and "undoes changes" at boot; disk space is low. Why does wall-switching make it worse, and what is the safe recovery order?

<details>
<summary>Model answer</summary>

The loop's two failing states: the update can't complete (likely disk-space starvation — updates need workspace) and the rollback at boot marks it uninstalled, so it retries. Wall-switching skips the OS's shutdown safety writes, so the rollback state itself becomes unreliable — risking a machine neither updated nor cleanly rolled back. Safe order: protect files first (copy criticals out) → free space → run the update deliberately on AC power, uninterrupted → verify (update history, one clean reboot). Prevention: scheduled update windows so the cycle can't restart.
</details>

## Q21 — Two definitions of "the file is deleted"

**Module 4 · CLO-4 · Difficulty 2/4 · Type: Conceptual**

Explain what actually happens when a file is deleted on (a) your laptop's SSD and (b) a synced cloud folder — and why (b) surprises people.

<details>
<summary>Model answer</summary>

(a) The filesystem marks the space *available* (directory entry removed; the OS may TRIM/unmap SSD blocks) — the content usually persists until overwritten, which is why undelete tools sometimes work, and why "delete" ≠ "secure erase". (b) Sync propagates the *intent*: the deletion is an event that replicates to the cloud and your other devices — the cloud copy disappears too, unless the service's version history/recycle window catches it (~30 days typically). (b) surprises people because "it's in the cloud" feels like a backup; a sync is a *mirror of your actions, including mistakes* — the course's recurring sync-vs-backup distinction.
</details>

## Q22 — Firmware, OS, application: who patches?

**Module 4 · CLO-4 · Difficulty 3/4 · Type: Comparative**

A laptop needs: a CPU security flaw mitigated, a Wi-Fi driver bug fixed, and a word-processor macro vulnerability closed. Which layer owns each fix, and why does one of the three update differently from the others?

<details>
<summary>Model answer</summary>

CPU flaw → **firmware/microcode + OS coordination** (vendor BIOS/microcode updates, usually via the OS's firmware-update mechanism); Wi-Fi driver → **OS/driver layer** (OS update or vendor driver package); macro vulnerability → **application** (office-suite update). The different one: firmware — it updates *rarely and cautiously* (a failed firmware update can brick the device, so vendor-gated, user-confirmed installs with power requirements) versus OS/app auto-updates. Good answers name the risk asymmetry as the reason, not just the layer.
</details>

## Q23 — The $99 laptop decision

**Module 4 · CLO-4 · Difficulty 3/4 · Type: Extended problem-solving**

A first-year with a ₹/£/$-limited budget chooses between: a used business-class laptop (8 GB RAM, SSD, 2-year-old, 1-year warranty), a new budget laptop (8 GB, SSD, full warranty), and a slightly better used machine with no warranty. State the three criteria that should decide it, pick one, and defend against the strongest counter-argument.

<details>
<summary>Model answer</summary>

Criteria: **reliability/service** (warranty + local serviceability — a broken machine is zero study capacity), **capability fit** (8 GB + SSD is the real floor for coursework; beyond that, marginal CPU gains don't matter), **total cost of ownership** (price + likely repair + battery). Defensible pick: the used business-class with warranty — business build quality + service coverage beats "new" as a proxy for reliability. Counter-argument ("used = hidden wear, battery gone") answered: battery is replaceable and cheap relative to a failed mainboard; the warranty converts unknown-wear risk into a service claim — the no-warranty better-spec option is the one that quietly fails the reliability criterion. Marks live in the *criteria being explicit* and the defence engaging the best objection.
</details>
