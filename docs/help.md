# Help — Study Tips, FAQs, and Support

This page collects the practical know-how that keeps students on track: how to study for this course, answers to common questions, and where to get help when you are stuck.

---

## 1. How to study for this course

1. **After each lecture (same day, 20 minutes):** re-read the lecture page and answer its *Check your understanding* questions from memory. Check yourself honestly.
2. **Before the next lecture (15 minutes):** skim the "Looking ahead" section of the previous lecture to activate prior knowledge.
3. **Weekly (60–90 minutes):** do the lab early, not on the due date. Labs are designed to be finished in one sitting.
4. **Concept journal:** keep a single page per module listing key terms and one example each. Explaining a term aloud in your own words is the fastest way to find gaps.
5. **If you fall behind:** contact the instructor early. The best-10-of-14 quiz policy absorbs ordinary misses; it cannot absorb weeks of silence.

## 2. FAQ

**Do I need programming experience?** No. This course assumes zero programming background; it prepares you for programming courses that come later.

**Which computer or operating system do I need?** Any recent Windows, macOS, or Linux machine with internet. Labs are platform-neutral; where platform differences matter, handouts show both paths.

**Which spreadsheet should I use?** Any of Microsoft Excel, Google Sheets, or LibreOffice Calc. Where features differ (for example lookup functions), the handout notes the differences.

**Why learn binary when computers convert everything for me?** Because data sizes, encodings, IP addresses, permissions, and errors all become comprehensible once you read binary and hex. It is the single highest-leverage skill in this course.

**Is ChatGPT-style AI allowed for assignments?** Only where a task sheet explicitly permits it, and only with disclosure — see L28 and the [Syllabus](syllabus.md#7-course-policies) for the reasoning.

**Is "hacking" covered?** You will learn how security works and how attackers think at a conceptual level (L29). Techniques for attacking real systems are out of scope; all course security exercises run on simulated, authorized examples only.

**What if my laptop breaks?** University lab machines satisfy every requirement. Save course work to cloud storage so you can switch machines.

## 3. Getting help

| Situation | Where to go |
|---|---|
| Course content question | Ask in lecture or the course LMS forum |
| Lab stuck > 30 minutes | Post the exact step and error to the LMS forum |
| Grades or extensions | Email the instructor from your university account |
| Accessibility accommodations | Institutional accessibility office + instructor, Week 1 |
| Technical account issues (LMS, email) | University IT helpdesk |

When asking for help, include: what you tried, what you expected, what happened. Screenshots help; photograph errors clearly.

## 4. Wellbeing and workload

The weekly rhythm is deliberately steady: two lectures, one lab, occasional activity. If the workload ever feels unmanageable, talk to the instructor before the deadline, not after. Extensions requested in advance are routinely granted for good cause.

## 5. Keyboard and efficiency basics (for mixed-literacy students)

- Learn `Ctrl/Cmd+C` (copy), `Ctrl/Cmd+V` (paste), `Ctrl/Cmd+Z` (undo), `Alt+Tab` / `Cmd+Tab` (switch windows), `Ctrl/Cmd+F` (find).
- Use the operating system search (Start menu / Spotlight) to open programs instead of hunting icons.
- Name files with meaning from day one — see L11 for the full convention.
