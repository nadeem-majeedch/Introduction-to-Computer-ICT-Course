# Lab 1 — Digital Basics and System Orientation

> **Assigned:** L01 · **Due:** end of Week 2 · **Module 1**

## Purpose

This lab establishes your working environment and the "find the computer" analytical habit from L01. By the end you will have a course-ready machine, a course folder structure, and a device inventory that demonstrates the definition of a computer.

## Before you start

- A computer with internet access (any OS).
- 60–90 minutes; nothing is installed system-critically in this lab.

## Part 1 — System orientation (20 min)

Record the following about your machine (screenshots where noted):

1. OS name and version (Windows: Settings → System → About; macOS:  → About This Mac; Linux: `uname -a` in a terminal).
2. CPU model and core count; installed RAM.
3. Storage: total and free space.
4. Screenshot of each display.

## Part 2 — Course workspace (20 min)

1. Create the folder tree exactly:

```text
ict-course/
├── lectures/
├── labs/
│   └── lab-01/
├── project/
└── resources/
```

2. Write the absolute path of `lab-01/` on your OS (you will re-derive this in Lab 3).
3. Set up your cloud sync or university storage for this folder (3-2-1 preview from L11 — full backup work arrives there).

## Part 3 — "Find the computer" inventory (30 min)

Pick **eight** devices you interacted with today. For each, fill a table:

| Device | Contains a computer? (Y/N) | Input | Processing evidence | Output | Storage | Class (L03) |
|---|---|---|---|---|---|---|

Rules: at least one "N" with a defence, at least one embedded system, and processing evidence must be *observable* (what changes? what responds?), not asserted.

## Part 4 — Reflection questions (15 min)

1. Which of your eight devices was hardest to classify, and what criterion finally decided it?
2. State the four-part definition of a computer and map it to your phone in one sentence each.
3. Why does this course organize work in a fixed folder tree? Connect to one lecture idea.

## Expected observations and troubleshooting

**You should see:** an About screen naming CPU/RAM; a folder tree matching Part 2 exactly; eight rows in Part 3's table with *observable* processing evidence ("screen updates when I type", not "it computes").

**If something goes wrong:**
- *About screen hidden by institution policy* → use the manufacturer sticker/manual plus the model number looked up on the vendor's support page; note the substitution in your submission.
- *Second display absent* → record the display settings page showing a single display; Part 1 only needs what exists.
- *Cloud sync unavailable* → skip Part 2 step 3, note it, and complete it in Lab 3's backup work.

**Accessibility alternative:** screen readers read system-info panels fine — submit a text file of the read values instead of screenshots; the device table works entirely as text. If any part is inaccessible on your machine, university lab machines or a submitted written plan with the Help desk satisfy the criterion — see the [Practical Lab Workbook](workbook.md#accessibility-and-fallbacks).
